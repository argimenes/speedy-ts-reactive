# Project working conventions

- Put major new features behind a feature flag, enabled by default unless the user's specification says otherwise. This applies to new features; do not change existing feature defaults without a request.
- If it is unclear whether a change is substantial enough to warrant a feature flag, ask the user before implementing it.
- Document saving is manual. Edits mark the Document tab dirty; Command-S/Control-S saves the active Document to its opened filename in Mutable JSON. Do not add background document saves or automatic Markdown sidecars. Dirty indicators must use cheap per-document state, not serialization or document scans during typing.

# Editor performance conventions

- Uninterrupted, low-latency typing is the chief priority for editor changes. Preserve immediate text feedback and correct caret, selection, IME and undo behaviour. Optional UI updates, annotation drawing and background services must not introduce input lag.
- Ordinary typing must not scan the vault, capture a full document snapshot, or recompute unrelated Explorer rows. Its cost should follow the affected text and annotations, not the number of unrelated files or open documents.
- Prefer valid, shared DOM geometry caches when locating cells, annotation ranges, hit targets and SVG decorations. Do not independently remeasure the same elements for each consumer or replace cached lookups with repeated DOM traversal. The original editor in `src/library/original/modules/speedy/editor-new-2.js` is the design reference: frame-batched cell `x`, `y`, `w`, `h` measurements, retained `previousOffset` values and position comparisons to avoid unnecessary redraws. This is a design requirement for ongoing work, not a claim that the current SolidJS renderer already implements the full cache.
- Coalesce necessary geometry refreshes in an animation frame, read layout before writing DOM/SVG, and limit measurement to invalidated regions and their reflow dependencies. Scheduling a full scan in `requestAnimationFrame` does not make it inexpensive. Retain previous/current geometry or deltas so consumers can skip unchanged output; reuse the same measured geometry for annotation SVG shapes.
- Make geometry cache validity explicit. Account for edits, wrapping, font changes, resizing, zoom/transforms and scrolling in the appropriate coordinate space; distinguish mounted occurrences and release removed elements. Reuse valid geometry, never stale positions. Refresh only what correctness requires; do not add an unconditional whole-document cell sweep to typing.
- Keep reactive dependencies narrow. File highlighting should observe file identity/location, not aggregate document properties containing save status. Memoize shared derivations instead of repeating them in each control or row.
- Trigger derived UI work from changes to its actual source data, not generic text-edit or document-revision events. Backlinks depend on entity-reference standoff properties: ordinary typing and automatic offset rebasing must not rebuild their inventory or refresh summaries. Resolve current occurrence ranges when previewing/navigating. Debounce or coalesce genuinely necessary burst work only after eliminating irrelevant triggers.
- When changing work triggered by text edits, add a meaningful regression check for bounded work (such as property reads, layout reads, full-document scans, snapshots, network requests or unrelated DOM updates). Correct output alone is not sufficient. Use the real Flint typing benchmark for before/after measurements when performance is in question; do not treat headless frame timing as guaranteed user-visible latency.
- Keep persistence, full validation, vault discovery and indexing outside the per-keystroke path. Deferring unnecessary work is not a substitute for removing it; deferred work must retain cancellation and stale-result checks where applicable.
