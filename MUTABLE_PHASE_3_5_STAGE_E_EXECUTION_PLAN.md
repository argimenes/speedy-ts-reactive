# Stage E execution plan

Stage E is authorised by the user's collection-interchange request. This resolves Section 9's go/no-go decisions without redesigning Phases A–D. Use the existing default-on `documentInterchange` flag.

1. **Selection and scope.** Explicit folder selection uses the browser directory picker where available, with `<input webkitdirectory>` as fallback. The browser supplies files; no server-side source-path discovery or symlink following is introduced. Validate every relative path, reject traversal/absolute paths and case/Unicode aliases, and exclude hidden directories/files, `.git`, `.mutable`, credentials and unsupported binaries with an inventory diagnostic. File handles/OS paths are never persisted. Destination selection is an explicit Cavern-relative directory.
2. **Dialect.** `mutable-markdown-vault-v1`: the existing CommonMark/GFM-table parser plus an adapter on its text nodes for `[[path|label]]` and `![[path]]`. Conventional Markdown links/images use the same resolver. Resolve exact relative or Vault-root wiki paths (including explicit `/` root paths); conflicting candidates remain ambiguous; extensionless document paths can resolve only uniquely. Never search by basename/title. Heading/block fragments, document transclusion, frontmatter aliases/metadata and plugin syntax are retained with diagnostics rather than guessed. Links become scoped native Document references, not invented Entity records. Preserve-source mode retains exact decoded Markdown/HTML plus reconciliation metadata and managed attachment bindings.
3. **Two passes and collisions.** Inventory and hash all admitted files; allocate all document identities and destination paths before conversion. Preview source → destination paths, skips, diagnostics and collisions. Default keep both using deterministic ` (2)`, ` (3)` suffixes; skip/abort alternatives. Account for case-folded/Unicode collisions and file/directory conflicts. No overwrite option. Revalidate paths before each create-only save; a collision introduced after review stops that document for another review.
4. **Batch publication.** The separate **Import and Save collection** confirmation authorises explicit native JSON writes. Prepare one document through MutableFragment/managed assets, capture its native generation, journal it, then call the existing conflict-protected native writer with an empty baseline. Do not mount the entire collection in the active editor. Completed documents remain saved; cancellation stops future operations and reports completed/skipped/failed/pending. This is not a global Undo; subsequent edits to opened documents use ordinary history/manual save. No external source is overwritten and no Markdown sidecar is created.
5. **Recovery.** A bounded IndexedDB journal, coordinated by browser Web Locks, stores the inventory fingerprint, allocated identities/paths, status and at most one in-flight captured generation. A refused journal write prevents dispatch. Resume is explicit, requires the same Cavern/destination, reselection and full source-hash revalidation, plus destination verification. Retry an uncertain save with its exact original generation/bytes using existing idempotent writer recovery. Completed paths must still match their acknowledged native hashes; changed or missing files block resumption. Review/export the saved batch report without source access. Explicit abandonment is allowed only without an unacknowledged save and retains all completed files/assets. No automatic background replay, overwrite, rollback of saved files or asset deletion.
6. **Assets.** Only inventoried PNG/JPEG originals are admitted through the existing Cavern asset service, validation and hash deduplication. Unselected/outside-root/missing/ambiguous resources stay inert with diagnostics. Never fetch remote images. Existing per-document image limits apply. Published originals remain retained under the approved conservative policy.
7. **Export.** Explicitly select saved native documents from a reviewed destination-directory inventory. Capture only that set; rewrite internal links using its shared path map. Export Markdown/source files and required originals once in a downloadable ZIP, with a reconciliation manifest. Reuse native decoding, semantic projection, managed-original verification and Stage C ZIP machinery; no dependency crawl, viewer/theme generation or website. Missing/foreign assets and projection losses are reviewed, never silently fetched.
8. **Limits and responsiveness.** Import: 1,000 text documents, 5,000 selected files and 512 MiB total; existing 8 MiB/200,000-character text and 10 MiB/image, 20 images/40 MiB per-document limits remain. Hash/parse/materialize in cancellable workers; one document/asset operation at a time, releasing document trees after each save. Download export uses a 60 MiB content budget and is capped at 64 MiB ZIP/96 MiB expanded and 5,001 members; larger collections require a smaller explicit selection. This bounded download does not enlarge `.inkpkg` limits. No collection subscriptions or work on ordinary keystrokes.

Qualification covers nested/cyclic links, ambiguous/missing references, malicious paths, collisions/races, source preservation, original assets, cancellation and restart, exact-generation retry, round-trip export/re-import, browser selection and matched Flint typing measurements.
